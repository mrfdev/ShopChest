## Failure found and verification repeated

An incremental check in the original checkout initially reused generated build
`792` metadata while expecting `793`. `processResources` now declares all seven
expanded release values as task inputs. A regression check generated build
`792`, then ran `verifyGeneratedReleaseMetadata` at the default build `793`
without cleaning: Gradle detected the changed `buildNumber` input, regenerated
the resources, and passed verification. The canonical clean build and both
runtime test suites were then rerun successfully.

The first persisted-data smoke harness waited for wording specific to an absent
currency template. The fixture already had a captured template. Its response
assertion was corrected and the complete smoke run repeated. A transient
inactive row during initial chunk loading was absent from both final audits.
